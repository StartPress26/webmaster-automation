# StartPress 확장 프로그램 프론트

고객사·메인 사이트·IndexNow 설정·새 글 저장 및 알림을 기존 FastAPI에 연결한 프론트입니다.
로컬 웹과 Chrome에 설치하는 Manifest V3 패키지로 실행할 수 있습니다.

## Chrome에 로드

```bash
cd extension
npm ci
npm run build
```

1. Chrome에서 `chrome://extensions`를 열고 개발자 모드를 켭니다.
2. **압축해제된 확장 프로그램 로드**에서 프로젝트의 `extension/dist` 폴더를 선택합니다.
3. 도구 모음의 StartPress 아이콘을 누르면 관리 화면이 새 탭으로 열립니다.

원본 설정은 `public/manifest.json`, Chrome이 읽는 빌드 결과는 `dist/manifest.json`입니다.
`src/background.ts`는 `dist/background.js`로 빌드되며 아이콘 클릭만 처리합니다.
코드를 변경하면 다시 빌드하고 확장 프로그램을 새로고침한 뒤 관리 탭도 다시 여세요.

설치된 확장 프로그램은 `http://127.0.0.1:8000`의 FastAPI로 직접 연결하므로 아래 개발 서버가 실행 중이어야 합니다.
웹 개발 서버의 `/api` 프록시는 기존대로 유지합니다. `.env`나 인증 파일을 확장 프로그램에 복사하지 않습니다.
현재 호스트 권한은 로컬 API용 `http://127.0.0.1/*`만 선언하며 Chrome 호스트 권한은 포트별로 제한되지 않습니다.
팀 배포 시 API 주소와 허용 호스트를 운영 HTTPS 서버에 맞게 변경해야 합니다.

이 단계는 설치·관리 화면 실행 구성입니다. 네이버 탭 목록·선택·Content Script·GUI 조회는 아직 구현하지 않았고 해당 권한도 요청하지 않습니다.
예시 화면만 보려면 열린 관리 화면의 URL에 `?mode=demo`를 붙이세요.

## 실행

프로젝트 루트에서 기존 `startpress` 환경과 PostgreSQL을 사용해 서버를 실행합니다.
개발 DB 설정은 기존 환경을 따르며 `.env`를 프론트로 복사하지 않습니다.

```bash
conda activate startpress
PYTHONNOUSERSITE=1 python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

다른 터미널에서 프론트를 실행합니다.

```bash
cd extension
npm ci
npm run dev
```

- `http://127.0.0.1:5173/`: 실제 API 모드. 저장 버튼은 DB에 반영되며 알림을 선택하면 실제 IndexNow 요청이 발생합니다.
- `http://127.0.0.1:5173/?mode=demo`: 예시 모드. 서버 호출·DB 저장·외부 전송 없이 동작합니다.

Vite 개발 서버가 `/api` 요청을 `127.0.0.1:8000`의 기존 경로로 전달합니다.
서버 연결 실패 시 오류와 목록 재조회 버튼을 표시하며 예시 데이터로 자동 대체하지 않습니다.
빌드 결과를 별도 호스팅할 때는 `/api`를 FastAPI로 전달하는 역방향 프록시 설정이 필요합니다.
팀 배포 전 팀원 인증·HTTPS를 추가해야 합니다.

## 연결 범위

첫 화면은 **고객사 대시보드**입니다. 왼쪽 위에서 고객사를 선택하고, 발행 알림·색인 상태 화면의
블로그 선택에서 해당 고객사 소속 사이트를 고릅니다. 고객사 관리는 전체 고객사를 대상으로 합니다.
대시보드에는 등록 블로그·글 수, Google·Bing별 저장 상태, 최근 오류 건수와 블로그별 현황을 표시합니다.
통계는 DB에 등록된 글만 대상으로 하며 메인페이지를 제외하고 비활성 항목은 포함합니다.
고객사를 전환하면 글 초안·선택 블로그를 분리하고 이전 고객사의 늦은 통계 응답은 무시합니다.
상세 집계 기준은 [대시보드 API](../docs/dashboard-api.md)를 참고하세요.

| 기능 | API |
|---|---|
| 고객사별 대시보드 통계 | GET `/clients/{id}/dashboard` |
| 고객사 등록·목록 | POST·GET `/clients` |
| 사이트 정보 등록·고객사별 목록 | POST·GET `/sites` |
| IndexNow 설정 조회·교체 | GET·PUT `/sites/{id}/indexnow-settings` |
| 글 저장·선택적 IndexNow 알림 / 저장된 글 목록 | POST·GET `/sites/{id}/pages` |
| 저장된 검사 결과 / 새 Google·Bing 조회 | GET·POST `/sites/{id}/inspections` |

- 사이트 정보 저장은 실제 검색엔진 등록·소유 확인과 구분합니다.
- 목록은 limit·offset 페이지를 끝까지 조회하고 서버 UUID를 사용합니다.
- IndexNow 설정 조회는 `configured`, `key_location`만 사용합니다. 키 원문은 설정 제출 때만 입력하며 화면 모델·로컬 저장소에 보관하지 않습니다.
- 설정이 없거나 불일치하면 직접 알림을 막지만 알림 체크를 해제해 글만 저장할 수 있습니다.
- 글 제목과 URL을 같은 순서로 한 줄씩 입력합니다. 여러 글은 순차 요청하며 글별 DB 저장·알림 결과를 별도로 표시합니다.
- HTTP 201도 알림 성공을 뜻하지 않습니다. `accepted`, `key_pending`, `failed`, `unknown`, `skipped`를 따로 표시합니다.
- 결과 불명·서버 오류 시 남은 전송을 중단합니다. 쓰기 요청은 자동 재시도하지 않습니다.
- 이미 저장했거나 저장 여부가 불명확한 글은 같은 화면 세션에서 다시 보내지 않습니다.
- 글 목록은 GET으로 다시 읽을 수 있지만 알림 재시도 API·서버 제출 이력은 아직 없습니다. 이번 알림 결과와 이력은 메모리에만 유지되므로 새로고침하면 사라집니다.
- 고객사 요청·블로그 링크 경로는 문구·메모만 준비하며 글 DB 저장·외부 메시지 전달·실제 블로그 발행을 수행하지 않습니다.
- 색인 상태 화면에서 메인페이지·글을 선택하면 GET으로 저장된 엔진별 요약 상태를 읽습니다. 페이지 진입·엔진 선택만으로 외부 조회를 실행하지 않습니다.
- Google·Bing의 인덱스 업데이트 버튼은 선택한 대상 UUID와 엔진을 POST로 한 번 보내 실제 조회·DB 저장을 실행합니다. 오류 시 이전 판정·마지막 성공 관측은 유지하고 저장된 오류를 다시 읽습니다. 자동 재시도하지 않습니다.
- 네이버는 로그인된 작업 탭 연결이 필요하므로 버튼을 유지하되 비활성화합니다. 서버 조회 API에는 네이버를 보내지 않습니다.
- API가 제공하지 않는 크롤링 시각·제출 이력을 생성하지 않습니다. Bing의 crawled를 indexed로 바꾸거나 unknown을 미색인으로 바꾸지 않습니다.
- 예시 모드는 여전히 외부 요청 없이 가짜 관측값으로 동작합니다.

## 검증

Node.js 24 환경에서 확인했습니다.

```bash
npm test
npm run build
```

테스트는 주입한 가짜 HTTP 응답으로 요청 필드·페이지네이션·오류 메시지·순차 실행·중단 정책을 검증합니다.
jsdom으로 실제 화면 코드를 실행해 고객사 전환·블로그 이동·초안 분리·응답 순서도 확인하며 실제 DB나 검색엔진을 호출하지 않습니다.

## 오류 화면

- 공통 오류 모델은 HTTP 상태·코드·입력 위치·작업 종류를 보존하고 원문 입력·예외 문맥은 버립니다.
- 오류 카드에는 실패한 작업, 확인된 원인, 다음 행동을 표시합니다. 오류 정보는 펼쳐서 확인할 수 있습니다.
- 입력 오류는 해당 필드의 설명과 `aria-invalid`에 연결하고, 입력을 유지한 채 첫 오류로 포커스를 이동합니다.
- 화면을 다시 그려도 같은 사이트·화면의 작성 중인 값은 유지합니다. 키·키 파일 주소는 별도 초안이나 로컬 저장소에 직렬화하지 않으며, 같은 화면의 입력 DOM만 잠시 재사용하고 저장 성공 시 초기화합니다.
- Google 인증 오류는 API 연결 안내만 제공하며, 아직 없는 로그인·재연결 기능을 버튼으로 위장하지 않습니다.
- 검사 실패는 이전 성공 상태와 성공 시각을 유지하며 미확인·미색인으로 바꾸지 않습니다. 같은 오류를 중복 표시하지 않습니다.
- 글 처리의 일부 실패·대기·결과 불명은 경고로 안내합니다. 결과 불명인 글은 GET으로 저장 여부만 확인할 수 있으며, 목록에서 발견되지 않아도 미저장을 단정하지 않습니다.
- 복구 버튼은 목록·저장 결과를 읽습니다. 글 저장·알림 전송·새 색인 검사를 자동 재실행하지 않습니다.
- `http://127.0.0.1:5173/?mode=demo&error=auth`에서 외부 요청 없는 인증 오류 화면 예시를 볼 수 있습니다.
- 백엔드 오류 코드 저장에는 Alembic 0003이 필요합니다. 기존 오류의 세부 원인은 소급 추정하지 않습니다.

## 후속 방향

공식 API 색인 조회의 수동 실행은 연결했으며, 중앙 서버의 주기적 실행은 후속 작업입니다.
네이버 GUI 조회는 사용자가 로그인된 작업 탭을 준비하고 확장 프로그램에서 수동 실행하는 방향입니다.
네이버 인증 만료·추가 인증 시 중단하며 두 경로의 관측 결과와 마지막 확인 시각을 엔진별로 저장합니다.
