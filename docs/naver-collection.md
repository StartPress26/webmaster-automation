# 네이버 웹페이지 수집 요청

## 최신 적용·검증 상태 — 2026-11-17

- 현재 리팩토링된 `app/controllers.ts`에서 포커스 세션으로 기존 수집 runner를 감싼다. 새 모듈은 `extension/src/focus/`에 있으며 `main.ts`와 기존 네이버 클릭·접수 판독 흐름은 재구성하지 않았다.
- manifest에 `debugger` 권한과 Chrome 118 하한을 추가했다. 작업 중 디버깅 안내 배너는 나타날 수 있지만 사용자 탭을 활성화하거나 창 포커스를 바꾸지 않는다. 네이버 탭의 DevTools는 닫아야 하며, 연결 실패 안내가 나오면 확장 권한과 작업 탭을 확인한다.
- 실제 개발 확장에서 현재 client·host를 연결해 백그라운드 목록 로딩·사이트 선택·수집 화면 진입이 두 번 모두 성공했다. 각 실행 후 디버거 해제, 취소 시 중단·해제, 관리 문서 새로고침 후 해제, 임시 작업 탭 종료 시 중단도 확인했다. 사용자 탭 선택은 유지됐고 검증용 임시 탭·모듈은 정리했다.
- 실제 글 URL 입력·확인 버튼 클릭·IndexNow·수집 접수는 이번 검증에 포함하지 않았다. 수집 화면 진입 성공과 실제 접수·수집·색인 성공은 별개다.
- 프론트 232개 테스트·타입 검사·확장 빌드·diff 검사와 코드·보안 리뷰를 통과했다. 이번 수정은 프론트만 포함하며 백엔드 테스트는 다시 실행하지 않았다.
- 커밋 전 검토 보완: 해제 실패 안내가 두 번 표시되던 문제, 작업 중 연결 종료가 사용자 취소로 표시되던 문제, 주소를 볼 수 없는 탭 이동을 감지하지 못하던 문제를 고쳤다. 주소를 볼 수 없는 이동은 22초 안에 네이버로 돌아오지 않으면 인증 필요 안내로 중단한다. 이 동작의 실제 Chrome 확인은 아직 하지 않았다. 프론트 테스트는 236개다.

## 이전 수동 검증 상태 — 2026-11-17

- 현재 확장의 백그라운드 처리는 새 네이버 문서의 준비 실패로 `timeout` 또는 `site_missing`이 발생할 수 있다. 같은 문서를 탭 활성화 후 다시 검사하면 사이트 선택이 성공하는 현상을 재현했다. 실제 URL 수집 제출·접수는 아직 확인하지 못했다.
- 사용자가 다른 Chrome 탭을 계속 사용할 수 있어야 하므로 자동 포어그라운드 전환을 제품 해결책으로 적용하지 않는다.
- DevTools의 **Emulate a focused page**를 끔→켬→켬→끔으로 비교했다. 끄면 사이트 선택 실패, 켠 두 번은 관리 탭 선택을 유지하면서 새 문서 로딩·사이트 선택·수집 화면 준비까지 통과했다. 실제 URL 입력·확인 클릭·IndexNow 전송은 하지 않았으며 검증 설정은 원복했다.
- 이 결과는 수동 DevTools 검증이다. 현재 manifest에는 `debugger` 권한이 없으며 본 확장의 CDP 연결·에뮬레이션·해제 처리는 아직 구현하지 않았다. 별도 임시 실험 확장은 준비·정적 검토만 마쳤고 새 권한 승인과 런타임 검증은 남아 있다. 상세 상태는 `docs/HANDOFF.md` 최상단을 따른다.
- 커밋 전 재검증은 프론트 208개, 백엔드 단위 694개, UUID 임시 PostgreSQL 통합 7개와 타입 검사·빌드·diff 검사 통과다. 테스트 통과와 실제 외부 접수 성공은 별개다.

## 확인한 화면 구조

2026-11-16 로그인된 Chrome에서 다음 흐름을 읽기 전용으로 확인했다.

1. `/console/board`의 등록 사이트 링크를 선택한다.
2. `/console/site/summary?site=…`에서 **요청 → 웹 페이지 수집**을 연다.
3. `/console/site/request/crawl?site=…`에서 URL 입력칸과 **확인** 버튼을 사용한다.
4. **수집 요청 내역** 표의 `No / URL / 등록일` 열을 확인한다. URL 링크의 `href`는 전체 URL이고 표시 문구는 경로다. 등록일 표시 예시는 `26.11.16 19:07:01`이다.

이 조사에서는 실제 수집 요청을 제출하지 않았다. 입력칸의 사이트 주소는 `label`이며 `placeholder`가 아니다. 번호가 바뀌는 Vuetify 입력 ID와 생성된 CSS 클래스에 의존하지 않는다.

## 확장에서 사용

1. `cd extension` → `npm run build` 후 개발자 모드 확장을 새로고침하고 네이버 탭도 새로고침한다. 기존 스토어 설치본에 로컬 빌드가 자동 반영되지는 않는다.
2. **새 글 발행 알림 → 직접 알림**에서 사이트를 고르고 글 제목·URL을 입력한다.
3. 기존 **글 저장과 함께 IndexNow 알림 전송**과 별도로 **네이버 GUI로도 수집 요청**을 선택한다. 네이버 GUI는 기본 해제다. IndexNow를 끄고 네이버 GUI만 선택할 수도 있다.
4. **글 저장 및 발행 알림**을 누른다. GUI를 선택했다면 먼저 네이버 작업 탭을 확인한다. 후보가 하나면 자동 확인하고, 여러 개면 선택을 기다린다. 없으면 로그인된 네이버 탭을 준비하고 **탭 목록 다시 확인**을 누른다. 이 단계에서는 글 저장·IndexNow·GUI 제출을 아직 실행하지 않는다.
5. 탭이 준비되면 글 저장과 선택적 IndexNow를 처리한다. 신규 저장 URL과 아래 모달에서 승인한 기존 글만 네이버 GUI로 요청한다. 전체 색인 조회를 먼저 실행할 필요가 없다.
6. 발행 화면의 글별 저장·IndexNow 결과와 네이버 GUI 접수 결과를 각각 확인한다. GUI 요청 접수 확인이 수집·색인 완료를 뜻하지 않는다.

네이버 홈·가이드·콘솔의 일반 탭을 후보로 찾고, board가 아니면 상단 **웹마스터 도구**로 이동한다. 이후 등록 사이트 선택 → **요청 → 웹 페이지 수집** → URL 입력 → **확인** 순서다. 추가 인증이 필요하면 사용자가 직접 처리한다. 인증정보는 수집하지 않는다.

발행 중 취소하면 진행 중인 저장 응답은 확인하고 아직 보내지 않은 글과 GUI 요청을 중단한다. IndexNow 실패와 네이버 GUI 결과는 별개다. 글 저장 여부가 불명확한 배치는 추가 GUI 요청을 하지 않는다. 다른 사이트로 이동해도 시작 시 고정한 사이트·URL로 진행하며, 다른 사이트 화면에는 진행 안내와 취소 버튼만 보인다.

기존 전체 조회는 수집 요청을 실행하지 않는다. 접수 결과는 현재 관리 탭 메모리에 표시하며 `gui-inspections` API나 대시보드 색인 통계에 저장하지 않는다. 관리 탭을 닫으면 접수 표시가 사라지므로 네이버 요청 내역에서 확인한다. 이번 GUI 구현은 네이버이며 Bing은 기존 IndexNow 알림을 유지한다.

### 이미 DB에 등록된 글

생성 API의 `DUPLICATE_PAGE` 응답이면 기존 글을 조회해 고객사·사이트·정확한 URL·활성 상태를 확인한다. **이미 등록된 글입니다** 모달에 기존 제목·URL과 현재 선택한 요청 경로를 보여준다.

- **계속 요청**: 글을 다시 저장하지 않고, 선택한 IndexNow API 재알림과 네이버 GUI 수집을 실행한다. IndexNow만 선택해도 사용할 수 있다.
- **이 URL 건너뛰기**·닫기·Escape: 해당 URL에 대한 요청을 하지 않고 다음 글이 있으면 이어간다.
- 전체 발행 취소: 승인 대기와 남은 배치를 모두 중단한다.

DB 결과는 **기존 글 사용**으로 표시하며 IndexNow 접수·GUI 접수와 분리한다. 알려지지 않은 저장 오류를 기존 글로 간주하지 않는다. IndexNow 통신 실패는 기존 DB 존재를 유지한 채 접수 미확인으로 표시하고 자동 재전송하지 않는다. 기존 글이 비활성화·삭제·변경되어 서버 재검증에 실패하면 GUI도 실행하지 않는다.

기존 글 IndexNow 재알림에는 `POST /sites/{main_site_id}/pages/{page_id}/notifications` API가 필요하다. JSON `expected_url`과 서버의 저장 URL을 비교한다. **확장뿐 아니라 API도 업데이트해야 하며**, DB 마이그레이션은 없다. 자세한 계약은 `docs/pages-api.md`를 따른다.

## 스크립트 구조

- `extension/src/main.ts`: 관리 화면의 진입점. 상태·이벤트는 리팩토링된 `app/` 모듈에 있다.
- `extension/src/app/{events,actions}.ts`: 발행 폼 이벤트와 입력 처리.
- `extension/src/app/controllers.ts`: 포커스 runner 주입과 작업/해제 오류 안내 보존.
- `extension/src/background.ts`: 기존 아이콘 동작과 포커스 host 등록.
- `extension/src/focus/host.ts`: 서비스워커의 세션 소유·대상 검증·에뮬레이션·정리.
- `extension/src/focus/client.ts`: 관리 문서의 Port 수명·제한 시간·취소 signal 연결.
- `extension/src/focus/naver-runner.ts`: 연결 준비 후 기존 runner를 한 번 실행하고 결과와 원래 오류 보존.
- `extension/src/focus/{protocol,messages}.ts`: 고정 메시지와 사용자 안내.
- `extension/src/publication/controller.ts`: 입력 스냅샷, 탭 준비 → 글 저장/IndexNow → 네이버 GUI 실행·취소·별도 결과 상태.
- `extension/src/publication/tabs.ts`: 발행용 네이버 홈·가이드·콘솔 탭 후보와 재검증. 기존 색인 조회의 탭 규칙은 유지한다.
- `extension/src/publication/view.ts`: 발행 폼 밖의 탭 선택과 URL별 GUI 접수 결과.
- `extension/src/engines/naver/collection.ts`: 상단 링크·요청 메뉴 클릭, URL 입력·확인 1회 클릭·새 접수 내역 판독.
- `extension/src/engines/naver/collection-automation.ts`: `runNaverCollectionAutomation`으로 사이트와 URL별 순차 진행.
- `extension/src/engines/naver/content.ts`: 동일 확장 관리 화면의 `open_board / select_collection_site / open_collection / request_collection` 명령 처리. 문서 토큰·공유 작업 잠금·취소 검증.

이전 조회 종료 후 수집 폼용 `collection-view.ts`와 검사 컨트롤러의 수집 진입점은 제거했다. runner는 선택된 `WorkTab`, 저장 확인된 `readonly ClientInspectionTarget[]`, `signal / onStart / onResult` 훅을 받는다. 전체 대상의 같은 사이트 범위·URL 길이·중복을 실행 전에 검사하며, `onResult`가 끝나야 다음 URL로 진행한다.

## 접수와 색인 판정

`NaverCollectionReceipt`는 다음 값을 반환한다.

| 필드 | 값 | 의미 |
|---|---|---|
| `requestStatus` | `accepted` | 대상 URL의 새 요청 내역 확인 |
| `collectionStatus` | `unknown` | 검색로봇 수집 완료 미확인 |
| `indexStatus` | `unknown` | 색인 완료 미확인 |
| `registeredAtText` | 네이버 표시 등록일 | 이번 접수 증거 |

제출 전 요청 내역을 기준으로 삼고, 같은 대상 URL의 새 등록일이 나타나야 접수로 판정한다. 기존 행·동일 등록일·행 재정렬·DOM 교체만으로 접수 성공으로 처리하지 않는다. 표시 등록일은 한국 시각으로 해석하고 요청 시각 이후인지 초 단위로 확인한다. 브라우저 시계와 서비스 표시 시각에 차이가 있거나 같은 초에 재요청했다면 접수를 확정하지 못할 수 있다.

확인 클릭 이후 시간 초과·취소·탭 이동·응답 연결 종료는 `receipt_unconfirmed`다. 이미 전송됐을 수 있으므로 **네이버 요청 내역을 직접 확인하고 자동 재요청하지 않는다**. 낯선 오류·한도 안내도 성공으로 추측하지 않는다. 취소는 이미 보낸 요청을 철회하지 않는다.

네이버 공식 안내도 요청된 URL의 수집이 즉시 진행되지 않으며 수집 성공이 검색 노출을 보장하지 않는다고 설명한다. [네이버 수집요청 및 검색제외 가이드](https://searchadvisor.naver.com/guide/request-crawl)
