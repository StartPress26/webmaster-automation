# Chrome 확장 프로그램 전환 결정

갱신일: 2026-11-03 (Asia/Seoul). 설계 결정 문서이며 확장 프로그램 구현·실제 동작 검증 완료를 뜻하지 않는다.

## 결정과 기존 기능

설치형 앱 + Playwright 자동 로그인 대신, 팀원이 평소 사용하는 Chrome 프로필에 확장 프로그램을 설치하고 직접 로그인하는 방향을 채택한다. 확장 프로그램은 작업 탭의 화면을 조작하고 중앙 FastAPI를 통해 공용 PostgreSQL에 업무 데이터와 결과를 저장한다. 확장 프로그램에 DB 비밀번호를 배포하지 않는다.

main에는 고객사·메인 사이트 API, SQLAlchemy·Alembic, Google·Bing 공식 API 어댑터, IndexNow·발행 알림 서비스가 이미 있다. 엔진의 모든 기능이 관리 API에 연결돼 있지는 않으며, 글 등록 API·팀원 인증·작업 배분·결과 저장은 추가 구현이 필요하다.

## 로그인봇 실험 종료

[feat/ai-login-bot 브랜치](https://github.com/StartPress26/webmaster-automation/tree/feat/ai-login-bot)는 실험과 테스트를 보존하고 main에 병합하지 않는다. 확장 프로그램이 해당 Python 로그인봇을 실행하는 구조로 만들지 않는다.

사용자가 전달한 별도 실험에서는 설치된 Chrome을 `channel="chrome"`으로 실행하고 별도 영구 프로필에서 직접 로그인해 서치어드바이저 인증 성공을 확인했다. 같은 프로필로 두 차례 재실행했으나 인증 성공을 확인하지 못했고 마지막에는 로그인 입력 화면을 확인했다. 이후 사용자가 네이버 보호조치 재발을 알렸다. 자동 비밀번호 입력·AI 전송은 수행하지 않았다.

이 결과는 이번 문서 작업에서 독립적으로 재검증하지 않았다. 보호조치 원인과 인증 유지 실패 원인은 미확정이며 확장 프로그램이 이를 해결한다고 보장하지 않는다. 추가 실로그인을 자동 재개하지 않는다. 프로필·쿠키·실행 로그는 비공개로 보존한다.

## 사용자 흐름과 탭 처리

1. 확장 프로그램 관리 페이지에서 고객사·사이트·글을 등록하거나 조회를 요청한다.
2. Service Worker가 작업을 관리하고 작업 탭의 Content Script가 화면을 읽고 조작한다.
3. 결과는 관리 페이지에 표시하고 인증된 중앙 API로 저장한다. 검색엔진 쿠키를 추출하거나 서버로 보내지 않는다.

처음에는 사용자가 선택한 기존 결과 탭을 읽는다. 운영 기본값은 같은 Chrome 프로필 안에 만든 작업 전용 비활성 탭으로 검토한다. 기존 탭은 사용자 조작과 충돌할 수 있으므로 임의로 선택·이동하지 않는다.

정확한 HTTPS 출처·허용 경로와 tabId를 함께 검사한다. 단계마다 현재 문서·사이트·조회 URL을 확인한다. 탭이 여러 개면 사용자가 선택하거나 확장 프로그램이 만든 탭만 사용한다. 닫힘·이동·로그아웃·접근 권한 없음은 구분해 중단한다. Chrome 재시작 후 tabId를 그대로 신뢰하지 않는다.

## 포커스·권한·복구

- 작업 중 탭을 활성화하거나 Chrome 창을 앞으로 가져오지 않는다. 추가 인증 시 중단하고 사용자가 작업 탭을 여는 버튼을 누르도록 안내한다.
- 비활성 탭의 조회·제출 성공은 미검증이다. 배경 타이머 제한·탭 메모리 해제·절전도 검증한다. 실패를 숨기기 위해 강제 활성화하지 않는다.
- 대상 서비스와 중앙 API에 필요한 권한만 요청한다. 전체 사이트 접근·쿠키 수집·로그인 폼 관찰은 기본 기능에 포함하지 않는다.
- 메시지의 작업 ID·단계·발신 탭·문서·URL·데이터 형식을 검사한다. 서버가 임의 코드나 클릭 스크립트를 보내 실행하는 구조는 사용하지 않는다.
- Service Worker 종료를 전제로 단계별 상태를 로컬 저장소와 서버에 보존한다. Chrome 종료·절전 중에는 작업이 실행되지 않는다.
- 재개 시 서버 배정과 현재 화면을 대조한다. 조회는 유효성을 확인해 재실행하고, 제출 결과가 불명확하면 무조건 재제출하지 않는다.

## 공용 데이터와 엔진별 경로

팀원 서비스 인증과 검색엔진 로그인/OAuth 연결은 분리한다. 사이트별 검색엔진 접근 권한을 확인한다. 서버가 작업을 원자적으로 배정하고 실행 ID·배정 유효기간으로 중복 실행과 오래된 결과 반영을 막는다. 실행 이력과 최신 상태를 분리하고 결과 업로드는 중복 저장 없이 재시도한다.

- 네이버: 기존 로그인 이후의 고정 조회·검증 조건을 TypeScript로 이식한다. 등록 사이트 `property_url`과 검사할 글 `target_url`을 분리한다. DOM 입력 이벤트·새 결과 식별은 별도 검증한다.
- Google·Bing: 기존 공식 API를 우선하고 API에 없는 필요한 기능만 탭 조작과 비교한다. Chrome 로그인만으로 서버의 API 인증이 되지 않으므로 OAuth/API 키 연결·보관 설계를 별도로 한다.
- Google URL Inspection은 저장된 색인 상태 조회이며 일반 URL 색인 요청·실시간 검사가 아니다. Bing 수집 관측도 색인 완료로 단정하지 않는다.
- IndexNow: 기존 공통 경로를 재사용한다. 접수 성공은 수집·색인 완료가 아니다.
- Brave: 동일한 웹마스터 콘솔·제출/조회 API가 있다고 가정하지 않는다. 공식 지원 경로 확인 전에는 미지원으로 둔다.

글 DB 등록, 블로그 실제 발행, 수집 요청 접수, 수집 확인, 실제 색인 확인을 화면과 저장 데이터에서 구분한다.

## 작은 검증 순서

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 이미 열린 네이버 결과 읽기 | 선택한 탭의 사이트·대상 URL·판정 메시지를 표시. 읽은 시각과 실제 조회 시각을 혼동하지 않음 |
| 2 | 단일 URL 조회 | 비활성 작업 탭에서 입력·확인·새 결과 식별. 다른 탭/앱 타이핑과 포커스 유지. 추가 인증 시 중단 |
| 3 | 중앙 서버 연결 | 팀원 인증·사이트/글 등록·작업·결과 저장. 두 PC가 같은 업무 데이터를 확인하고 권한·중복 저장 검사 |
| 4 | 여러 URL 처리 | 사이트별 순차 실행·취소·재개. 탭 이동/닫힘·Worker 종료·절전·통신 실패 복구 |

이 문서 PR은 공통 안내와 작업 규칙만 바꾼다. 로그인봇·Discord·Playwright 의존성·인증 설정과 로컬 실험 파일은 가져오지 않는다. 확장 프로그램 구현은 별도 feat/ 브랜치에서 단계별로 진행한다.
